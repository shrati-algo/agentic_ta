# ADR-008 — Switch detection from Canny+Hough+RANSAC to Threshold+Contour+Masked Hough

Status      :  Accepted
Date        :  2026-04-16
Deciders    :  Data Science Team, Phase 3 reviewers
Supersedes  :  The pipeline stages described in TRD v2.1 Section 6 and
               Architecture Section 17.1–17.3 (Canny, pick_innermost, RANSAC refine).

## Context

The Phase 3 measurement pipeline was initially implemented following
the TRD v2.1 recipe:

    grayscale -> CLAHE -> blur -> adaptive Canny -> cv2.HoughCircles
    -> pick_innermost(central region) -> RANSAC sub-pixel refinement
    -> mm conversion -> confidence score -> PASS/REVIEW/FAIL/ERROR

It was green on synthetic unit tests.  When we ran it against the first
pair of real trailing-arm images (`tests/fixtures/images/cam18jdleofhtlhj6_{L,R}.jpg`,
3072 x 2048, industrial amber lighting), it failed end-to-end:

- `cv2.HoughCircles` returned **500 to 800 candidate circles** per image
  because the plate texture under uneven illumination produces thousands
  of short edge fragments.
- `pick_innermost` walks the candidates ascending by radius within a
  central region.  With hundreds of small phantom circles in the plate
  texture, the smallest one is always noise, not the bushing hole.
- RANSAC refinement then tried to fit a circle to edge points in a 5-px
  annulus around a bogus seed, which either drifted further from the
  true bushing or converged on whatever happened to be nearby.

The pipeline reported diameters of 4–10 mm on parts whose bushing is
~20 mm, with confidence ≤ 0.55 and `status=ERROR`.

We explored several mitigations:

1. Raising `hough.param2` to suppress weak circles — reduced the
   candidate count from 500+ to ~150, but `pick_innermost` still
   chose the smallest noise circle.
2. Selecting by **darkest interior vs brightest surround** instead of
   smallest radius — this worked for a single image but is not a
   general rule; a scratched or stained bushing can be brighter than a
   shadow elsewhere.
3. Constraining Hough by the expected radius — this *is* reliable, and
   it is exactly what the operator reference script does.

## Decision

Replace the detection half of the pipeline.  Keep grayscale + blur.
Drop CLAHE, adaptive Canny, `pick_innermost`, and RANSAC refinement.
Use the contour-based detector from the operator reference script:

    grayscale -> Gaussian blur
    -> adaptive Gaussian threshold (inverted)
    -> morphological close
    -> external contours, sorted largest-area first
    -> for each contour:
           mask the grayscale, run cv2.HoughCircles with
           minRadius = (target_mm - radius_tolerance_mm) / 2 * ppm
           maxRadius = (target_mm + radius_tolerance_mm) / 2 * ppm
       return the first matching circle
    -> diameter_mm = 2 * radius_px * mm_per_px
    -> band classification:
           |delta| <= ok_band_mm            -> PASS
           |delta| <= somewhat_ok_band_mm   -> REVIEW
           outside                          -> FAIL
       (no detection -> ERROR)

The change is packaged as `algo-1.3.0`.

## Alternatives considered

- **Keep RANSAC, raise `param2` globally.**  Rejected — sensitive to
  lighting, still picks the wrong circle on cluttered parts.
- **Add a learned ROI detector to crop before measurement.**  Rejected
  under ADR-001 (no ML).  Contour-based isolation achieves the same
  effect deterministically.
- **Contour-based detector without target constraint.**  Rejected — the
  plate texture still produces spurious circles at the wrong scale.

## Consequences

### Positive

- Deterministic detection on cluttered, unevenly lit real images.
- Strong noise rejection: the Hough radius window throws away
  everything that is not the expected part scale.
- Fewer knobs that operators have to tune at deployment (no CLAHE clip
  limit, no RANSAC seed/iterations/inlier threshold).
- Natural classification: once a circle is detected in the target
  band, status is a simple distance check.
- Pipeline latency drops because RANSAC's 200-iteration inner loop is
  gone.

### Negative / trade-offs

- **The pipeline now requires a known target diameter.**  We add
  `target.diameter_mm` and `target.radius_tolerance_mm` to
  `algo_params`.  Multi-model plants will need to pick the right
  algo_params version per part (or extend the schema in a future ADR
  to carry a set of targets keyed by model).
- **Confidence is informational, not load-bearing.**  Status is derived
  from the diameter band only, not from a Hough/RANSAC confidence
  score.  This is *more* deterministic but gives operators less
  numerical wiggle for borderline calls.  The band width itself is the
  control knob.
- **Schema breaking change.**  `algo-1.2.0.yaml` no longer validates;
  it has been removed.  Any persisted measurement referencing it would
  need migration — none exist yet (greenfield).

### Neutral / follow-up

- The TRD's example algorithm description (Section 6) is now stale.  It
  has been updated in this commit to reflect the new pipeline.
- If we later need to support multiple part models in the same service
  instance, extend `algo_params.target` to a list, and look up by
  `model_id` on session start.  That is a future ADR, not this one.
- `docs/architecture.txt` Section 17 code sketches for Canny, RANSAC
  refine, and `pick_innermost` have been removed or replaced.
