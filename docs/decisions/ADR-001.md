# ADR-001 -- Classical CV only, no machine learning

Status      :  Accepted
Date        :  2026-04-16
Deciders    :  Data Science Team, Product Lead

## Context

The trailing arm measurement requires detecting the innermost circle on a
suspension component and computing its diameter in millimetres. A machine
learning approach (YOLO, segmentation model, etc.) would require GPU hardware,
a training pipeline, an annotation workflow, model versioning, and ongoing
retraining to handle drift. The plant does not have GPU infrastructure, and
the geometry being measured (a circle) is well suited to classical methods
(Hough transform, RANSAC fitting).

## Decision

The measurement pipeline uses only classical computer vision:
CLAHE, Gaussian blur, adaptive Canny edge detection, Hough circle detection,
innermost circle selection, and RANSAC sub-pixel refinement. No learned
components are permitted anywhere in the pipeline.

## Alternatives considered

- **YOLOv8 + circle regression** -- high accuracy potential, but requires GPU,
  annotation effort, training infrastructure, and model lifecycle management.
  Rejected: over-engineered for a single circular feature.

- **Hybrid (ML ROI + classical measurement)** -- uses a lightweight detector
  to crop the region of interest, then classical measurement. Rejected: adds
  an ML dependency without clear benefit, since the centre-region heuristic
  in algo_params achieves the same goal deterministically.

- **Template matching** -- brittle to scale and rotation changes across
  camera positions. Rejected.

## Consequences

- Positive: deterministic (same input, same output), fully explainable,
  no GPU required, no training pipeline, no model drift.
- Positive: faster to deliver and simpler to operate.
- Negative: accuracy depends on well-tuned algo_params and calibration;
  edge cases must be handled via parameter tuning, not learned features.
- Neutral: if a future measurement requires learned features, this ADR
  must be superseded with a new ADR and stakeholder agreement.
